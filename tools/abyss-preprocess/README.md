# abyss-preprocess

Config preprocessor for the `#include.abyss` config system.

## Purpose

Transforms simple DSL config files into compile-time C++ code for Abyss tools.

## Usage

```bash
abyss-preprocess \
  --app paper \
  --config-dir ~/.config/abyss \
  --output-dir build/abyss-config/paper \
  --generate-header build/generated/abysspaperConfigs.hpp
```

## Config Format

```cpp
#include.abyss <paper>

// Strings (with shell expansion)
wallpaper = "~/Videos/wave.mp4"
name = "My Config"

// Numbers
volume = 40        // int
opacity = 0.85     // float

// Booleans
audio = true
enabled = false

// Comments
// C++ style comments are supported
```

Store this as `~/.config/abyss/my-config.hpp`. The directive must be the first
line. This MVP accepts assignments to literal values, not arbitrary C++.
Normal `#include` directives are currently rejected; the planned app API and
C++ include support are not implemented yet. Files for other apps and ordinary
headers without the first-line directive are ignored.

## Generated Output

The preprocessor generates two types of files:

### 1. Processed Config (`.processed.hpp`)

```cpp
#pragma once
// Auto-generated by abyss-preprocess
// DO NOT EDIT

namespace abyss::paper::my_config {
    inline constexpr const char* wallpaper = "/home/user/Videos/wave.mp4";
    inline constexpr const char* name = "My Config";
    inline constexpr int volume = 40;
    inline constexpr float opacity = 0.85f;
    inline constexpr bool audio = true;
    inline constexpr bool enabled = false;
} // namespace abyss::paper::my_config
```

### 2. CMake Header (for build integration)

```cpp
#pragma once
// Auto-generated by abyss-preprocess

#include "/path/to/build/abyss-config/paper/my_config.processed.hpp"

namespace abyss::paper {
    inline constexpr const char* AVAILABLE_CONFIGS[] = {
        "my-config"
    };
    inline constexpr int NUM_CONFIGS = 1;
}
```

## Features

- ✅ Type inference (no need to specify types)
- ✅ Shell expansion (`~` and `$VAR`)
- ✅ Compile-time constants (zero runtime overhead)
- ✅ Stable output timestamps for incremental builds (source hashes are recorded
  in `manifest.json`; they do not skip parsing)
- ✅ Multiple configs per app
- ✅ Helpful error messages with line numbers

Keys must be non-reserved C++ identifiers beginning with a letter. Duplicate
keys and colliding filename namespaces (for example `a-b.hpp` and `a.b.hpp`)
are errors. Other filename characters and C++ keywords use a stable
`config_<sha256>` namespace. No filename determines which app API is selected.

## Integration with CMake

```cmake
include(../Abysstoolkit/cmake/AbyssConfig.cmake)

add_executable(myapp src/main.cpp)

# Add config support
abyss_add_config_support(myapp "paper")
```

This automatically:
- Runs `abyss-preprocess` before compilation
- Generates the config header
- Adds include paths
- Defines `ABYSS_CONFIG_AVAILABLE`

Outputs live under the current build directory, separately for each target.
The config directory is `$XDG_CONFIG_HOME/abyss` when `XDG_CONFIG_HOME` is
absolute, otherwise `$HOME/.config/abyss`. Configure with
`-DABYSS_CONFIG_DIR=/absolute/config/directory` to override it for tests or packaging.
Each build rescans the central config directory, including file additions,
removals and environment changes. Unchanged generated files keep their
timestamps. Generated constants are a build-time snapshot; changing a config
requires rebuilding and restarting its consumer. The generator does not choose
an active config or apply values to an app's runtime settings.

Installation places the executable in `bin` and this CMake module in
`share/abysstoolkit/cmake`. Python 3 is required to execute the preprocessor.

## Type Inference Rules

- **String**: Must be quoted with `"`; JSON escapes such as `\n`, `\"`, `\\` work
- **Bool**: `true` or `false`
- **Float**: Decimal or scientific notation (e.g., `0.85`, `1e-2`), finite float range
- **Int**: Signed 32-bit decimal number (e.g., `40`)

Both standalone and trailing `//` comments are supported outside strings.
An empty generated config set still provides `NUM_CONFIGS = 0` and an
`AVAILABLE_CONFIGS` sentinel array containing `nullptr`; iterate only up to
`NUM_CONFIGS`.

## Error Handling

```
ERROR in /home/user/.config/abyss/bad.hpp:3
  Cannot infer type for value: ~/video.mp4
  Strings must be quoted: "~/video.mp4"
```

## Future Features (Not in MVP)

- Arrays: `monitors = ["DP-1", "HDMI-A-1"]`
- Nested keys: `wallpaper.DP-1 = "..."`
- Multi-line strings: `description = """..."""`
- Schema validation with helpful errors
- Config inheritance/includes

## Architecture

```
User Config (.hpp)
    ↓
abyss-preprocess (Python)
    - Parse DSL
    - Type inference
    - Shell expansion
    ↓
Processed C++ (.processed.hpp)
    - constexpr values
    - Namespaced
    ↓
CMake Integration
    - Generated header
    - Include paths
    ↓
Compile Time
    - Zero overhead
    - Type safe
```

## Tests

Run `python3 -B tests/config/test_preprocess.py` from the repository root.
The CLI tests use only Python's standard library. Compiler/CMake checks run
when those tools are present. Test artifacts remain under the sibling
`_builds/abysstoolkit-config-tests` directory, configurable using
`ABYSS_TEST_WORK_DIR`.

See [AbyssConfig.cmake](../../cmake/AbyssConfig.cmake) for CMake integration.
